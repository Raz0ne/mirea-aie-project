## 1. Dataset

- Какой датасет выбран: `S06-hw-dataset-02.csv`
- Размер: (18000, 39)
- Целевая переменная: `target` (бинарная классификация: классы 0 и 1, доли классов ~73.75% и ~26.25%)
- Признаки: 
  - 35 числовых признаков (f01-f35) — непрерывные вещественные значения
  - 2 категориально-подобных признака (x_int_1, x_int_2) — целочисленные значения с малой мощностью
  - Датасет содержит нелинейные взаимодействия признаков и шум, что делает задачу более сложной для базовых моделей

## 2. Protocol

- Разбиение: train/test (test_size=0.2, random_state=42, stratify=y для сохранения пропорций классов)
- Подбор: CV на train (5 фолдов, оптимизация метрики ROC-AUC через GridSearchCV)
- Метрики: accuracy, F1, ROC-AUC
  - **accuracy** — общая точность классификации, показывает долю правильных предсказаний
  - **F1** — баланс между precision и recall, важна для бинарной классификации, особенно при дисбалансе классов
  - **ROC-AUC** — основная метрика для сравнения моделей, показывает способность модели разделять классы; особенно важна для датасета с нелинейными взаимодействиями и шумом, где важна не только точность, но и качество вероятностных предсказаний

## 3. Models

Опишите, какие модели сравнивали и какие гиперпараметры подбирали.

Минимум:

- **DummyClassifier** (baseline) — стратегия `most_frequent` для оценки базового уровня
- **LogisticRegression** (baseline из S05) — через Pipeline с StandardScaler для нормализации признаков
- **DecisionTreeClassifier** — контроль сложности через подбор гиперпараметров:
  - `max_depth`: [3, 5, 7, 10, 15, None]
  - `min_samples_leaf`: [1, 2, 5, 10]
  - `min_samples_split`: [2, 5, 10]
  - Лучшие параметры: max_depth=10, min_samples_leaf=10, min_samples_split=2
- **RandomForestClassifier** — подбор гиперпараметров:
  - `n_estimators`: [50, 100, 200]
  - `max_depth`: [5, 10, 15, None]
  - `min_samples_leaf`: [1, 2, 5]
  - `max_features`: ['sqrt', 'log2', 0.5]
  - Лучшие параметры: n_estimators=200, max_depth=None, min_samples_leaf=1, max_features='sqrt'
- **GradientBoostingClassifier** — подбор гиперпараметров:
  - `n_estimators`: [50, 100, 200]
  - `learning_rate`: [0.01, 0.1, 0.3]
  - `max_depth`: [3, 5, 7]
  - Лучшие параметры: n_estimators=200, learning_rate=0.1, max_depth=7

Опционально:

- **StackingClassifier** (с CV-логикой) — базовые модели: RandomForest (best), GradientBoosting (best), LogisticRegression; метамодель: LogisticRegression; используется 5-fold CV для обучения

Это демонстрирует преимущество ансамблевых методов на сложных датасетах с нелинейными взаимодействиями признаков и шумом. GradientBoostingClassifier показал очень близкий результат (ROC-AUC = 0.9338), что подтверждает эффективность бустинга на данном датасете.

## 5. Analysis

- Устойчивость: Проведено 5 прогонов с разными random_state (42, 123, 456, 789, 999) для RandomForestClassifier и GradientBoostingClassifier. Результаты показали хорошую устойчивость моделей: ROC-AUC варьировался в пределах ±0.01-0.02 от среднего значения, что говорит о стабильности ансамблевых методов и корректности выбранных гиперпараметров. Небольшие вариации связаны с разным разбиением данных на train/test.

- Ошибки: Confusion matrix для лучшей модели (StackingClassifier) показывает хорошее разделение классов с небольшим количеством ошибок. Модель правильно классифицирует большинство объектов обоих классов, что подтверждается высокими значениями accuracy (0.9147) и F1 (0.8276). Основные ошибки связаны с объектами, находящимися на границе классов, что характерно для датасетов с нелинейными взаимодействиями и шумом.

## 6. Conclusion

1. **Ансамбли превосходят базовые модели**: RandomForest и GradientBoosting показали значительно лучшие результаты по сравнению с DecisionTree и LogisticRegression на датасете с нелинейными взаимодействиями и шумом. StackingClassifier, объединяющий несколько моделей, показал наилучший результат.

2. **Контроль сложности критичен**: Для DecisionTree важен подбор max_depth и min_samples_leaf, чтобы избежать переобучения и улучшить обобщающую способность. Лучшая модель использовала max_depth=10 и min_samples_leaf=10, что предотвратило излишнюю сложность дерева.

3. **Честный ML-протокол**: Разделение на train/test с фиксированным random_state и стратификацией обеспечивает воспроизводимость результатов. Подбор гиперпараметров только на train через CV предотвращает data leakage и даёт честную оценку качества модели на тестовой выборке.

4. **Метрики важнее accuracy**: ROC-AUC и F1 дают более полную картину качества модели, особенно на сложных датасетах с нелинейными зависимостями. DummyClassifier показал accuracy=0.7375, но ROC-AUC=0.5, что демонстрирует важность использования правильных метрик.

5. **Permutation importance для интерпретации**: Позволяет понять, какие признаки действительно важны для модели, что важно для практического применения и понимания данных. На данном датасете один признак (f16) оказался значительно важнее остальных.

6. **Устойчивость ансамблей**: Ансамблевые методы (RandomForest, GradientBoosting) показали хорошую устойчивость к изменениям random_state, что подтверждает их надёжность для практического применения.
